# Verifikasi Database dan API: Soil pH Global

Tanggal: 25 September 2026 (WITA)

## A. Migration Review

**SAFE** untuk diterapkan sebagai migration terpisah.

`packages/backend/database/20260925_create_soil_ph_readings.sql` hanya menjalankan `BEGIN`/`COMMIT`, membuat tabel baru `public.soil_ph_readings`, dan membuat index baru. Tidak ada `DROP`, `DELETE`, `TRUNCATE`, `ALTER` terhadap tabel existing, maupun perubahan ke `sensor_readings`, `sensor_logs`, Rainfall, Authentication, atau Weather.

Struktur yang direview:

| Requirement | Hasil |
| --- | --- |
| Tabel pH baru | PASS — `public.soil_ph_readings` |
| `id` | PASS — `bigint generated by default as identity primary key` |
| `ph_value` | PASS — `numeric(5,2) not null` |
| Range pH | PASS — `check (ph_value >= 0 and ph_value <= 14)` |
| `measured_at` | PASS — `timestamptz not null default timezone('utc', now())` |
| Latest/history index | PASS — `soil_ph_readings_measured_at_idx (measured_at desc)` |

Migration idempotent untuk object yang sudah ada karena memakai `CREATE TABLE IF NOT EXISTS` dan `CREATE INDEX IF NOT EXISTS`. Catatan standar PostgreSQL: jika tabel/index dengan nama yang sama sudah ada tetapi definisinya berbeda, statement tidak memperbaiki atau memvalidasi definisi existing. Pada production saat verifikasi ini, tabel belum dapat di-query sehingga tidak ada konflik existing yang terdeteksi.

SQL final yang harus dijalankan melalui Supabase SQL Editor atau pipeline migration resmi project:

```sql
begin;

create table if not exists public.soil_ph_readings (
  id bigint generated by default as identity primary key,
  ph_value numeric(5,2) not null check (ph_value >= 0 and ph_value <= 14),
  measured_at timestamptz not null default timezone('utc', now())
);

create index if not exists soil_ph_readings_measured_at_idx
  on public.soil_ph_readings (measured_at desc);

commit;
```

## E. Root Cause Regression

Hasil berikut berasal dari unit test dengan Supabase mock. Production POST tidak dilakukan karena migration belum ada.

```text
pH POST creates Soil Moisture reading: NO
pH POST changes Soil Moisture lastSeen: NO
legacy pH payload can update Soil Moisture: NO
```

Evidence:

- `createSoilPhReading({ soil_ph: 6.4 })` menginsert tepat satu `{ ph_value: 6.4 }` ke tabel `soil_ph_readings`; tidak ada query ke tabel moisture.
- `insertSensorReadings()` menolak signature legacy `status: "pH Monitor"` bersama `soil_ph`/`ph` sebelum upsert sensor atau insert log.
- Jalur pH tidak memakai `sensor_id`, `sensor1..sensor6`, `kelembaban`, maupun `sensor_logs`; akibatnya tidak ada kode yang dapat memperbarui `created_at`, `lastSeen`, atau `isOnline` Soil Moisture.
